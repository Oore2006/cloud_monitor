    What you are looking at

    Monitoring

    Every server reports metrics (CPU, memory) at a fixed interval. A monitoring system stores them and draws charts. Real tools that do this: Prometheus with Grafana, AWS CloudWatch, Datadog.

    Load balancer

    Spreads incoming requests across healthy servers. In this app each healthy server gets an equal share. If one server dies, the others take its share and their CPU rises.

    Health checks

    The load balancer keeps asking each server "are you alive?". A server that fails is taken out of rotation so users never get sent to it.

    Alerting and thresholds

    An alert fires when a metric crosses a threshold. Here: CPU above 90% is critical. Good alerts are specific and tell you what to do next.

    Autoscaling

    The platform adds servers when average CPU stays high (scale out) and removes them when it stays low (scale in), so you pay only for what you need. In AWS this is an Auto Scaling Group; in Kubernetes, the Horizontal Pod Autoscaler.

    Self-healing

    When autoscaling is on, a crashed server is replaced with a fresh one after a few seconds, with no human involved.
